# MoreBC2 Editorial Style Guide

**Status:** Framework

## Purpose

This guide keeps MoreBC2 consistent, useful, and careful.

The site should help people understand BitcoinII (BC2) without confusing verified documentation, research, discussion, history, or opinion.

## Naming

Use:

- **BitcoinII** for the project name.
- **BC2** for the ticker.
- **BitcoinII Core** for the reference node and wallet software.
- **MoreBC2** for this community documentation project.

Avoid:

- Bitcoin2
- Bitcoin II, unless quoting a source that writes it that way
- BCII, unless quoting a source that writes it that way

## Core rule

MoreBC2 is not the source of truth. It is a map to the source of truth.

When possible, link readers to the original source: source code, release notes, official repositories, official websites, explorer data, or dated public statements.

## Content categories

Each page should clearly belong to one of these categories:

- **Documentation** — current, verifiable behavior.
- **News** — factual updates about things that happened.
- **Research** — technical explainers and analysis.
- **Discussion** — ideas, opinions, proposals, and open questions.
- **History** — older events and archived context.

## Status labels

Use one of these page status labels near the top of substantial pages:

- **Draft** — early working content.
- **Framework** — structure, policy, or coverage framework exists, but the page is not a verification claim.
- **Partial** — meaningful source-backed or tested coverage exists, but important areas remain incomplete.
- **Needs Review** — mostly written, but the relevant claims or current-state wording still need checking.
- **Reviewed** — a reviewer has checked the page at the stated scope, but that does not automatically make every claim Verified.
- **Verified** — the page-level verification standard has been met against strong evidence.

Historical or superseded material should be identified explicitly so readers do not mistake it for current information.

## Source strength

Prefer stronger sources:

1. Current BitcoinII source code.
2. Official BitcoinII release notes.
3. Official BitcoinII website or repositories.
4. Public explorer data.
5. Direct developer statements.
6. Community discussion.
7. Third-party summaries.

Do not present community discussion as implementation.

## Language rules

Use direct, plain language.

Good:

> The current source code defines a 10-minute target block spacing.

Bad:

> BC2 is definitely the fastest and best Bitcoin sister chain.

Good:

> This has been discussed by community members, but it is not currently documented as implemented.

Bad:

> This is probably coming soon.

## Uncertainty

Admit uncertainty clearly.

Use phrases like:

- Needs verification.
- Source needed.
- Current source code appears to show...
- This has not been confirmed by an official source.
- This page should not be treated as final.

## Opinion placement

Opinions, predictions, speculation, proposals, and community debate belong in Discussion or clearly labeled community writing.

They do not belong in Documentation.

## Crypto-specific caution

Avoid price hype, investment promises, and unsupported claims about future value.

MoreBC2 documents the ecosystem. It does not provide financial advice or market predictions.
