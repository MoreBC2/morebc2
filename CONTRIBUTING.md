# Contributing to MoreBC2

Thanks for helping improve MoreBC2.

This project is meant to be community-maintained, but it should not become a rumor archive or hype page. The goal is to make BitcoinII (BC2) easier to understand by organizing information and pointing readers back to verifiable sources.

## Good contributions

Good contributions include:

- Fixing outdated or incorrect information.
- Adding missing sources.
- Improving clarity.
- Adding wallet, mining, node, or developer guides.
- Creating exchange or infrastructure integration documentation.
- Documenting historical milestones.
- Moving opinion or speculation out of documentation sections.
- Opening issues for claims that need verification.

## Source preference

Use the strongest source available.

Preferred order:

1. Current BitcoinII source code.
2. Official BitcoinII releases and release notes.
3. Official BitcoinII website or repositories.
4. Public block explorer data.
5. Direct developer statements.
6. Community discussion.
7. Independent research or analysis.

Community discussion can be useful, but it should be labeled as discussion. It should not be presented as implemented behavior.

## Content labels

Use clear labels near the top of each page:

- **Documentation** — current verified behavior.
- **News** — factual updates.
- **Research** — technical explanation or analysis.
- **Discussion** — ideas, opinions, proposals, and open questions.
- **History** — past events or older context.

## Verification status

Each important page should include a verification block near the bottom:

```md
## Verification

**Status:** Draft / Needs Review / Verified / Historical
**Last reviewed:** YYYY-MM-DD
**Primary sources:**
- Source 1
- Source 2

**Notes:**
- Any uncertainty or caveats.
```

## Pull request checklist

Before opening a pull request, ask:

- Is this in the right category?
- Did I avoid presenting discussion as implementation?
- Are claims sourced?
- Did I use BitcoinII or BC2 rather than Bitcoin2?
- Did I clearly mark uncertainty?
- Did I avoid price hype, investment claims, or unsupported marketing language?

## Tone

Use plain, useful language. The site should help newcomers without talking down to experienced users.

## Naming standard

Use **BitcoinII** for the project name and **BC2** for the ticker. Avoid using **Bitcoin2** in MoreBC2 documentation unless quoting or documenting historical third-party usage.
