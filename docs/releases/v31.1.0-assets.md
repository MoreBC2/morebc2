# BitcoinII Core v31.1.0 release assets

**Category:** Releases
**Status:** Reviewed / Current bounded evidence
**Last reviewed:** 2026-09-12

## Summary

This page records the current GitHub release inventory and bounded local-integrity evidence for BitcoinII Core `v31.1.0`.

The release currently contains **six uploaded binary archives**. GitHub reports a SHA-256 digest for each uploaded asset. MoreBC2 has independently calculated and matched the SHA-256 of the Windows Qt archive used in the September 11 Windows runtime test.

That is stronger than hosting metadata alone for that one retrieved archive, but it is still **not publisher authentication**. MoreBC2 has not established a BitcoinII-signed checksum manifest, detached asset signatures, a trusted BitcoinII release-signing-key procedure, or reproducible-build proof for `v31.1.0`.

## Tag and commit state

The Git ref `refs/tags/v31.1.0` currently points **directly to a commit**, rather than to an annotated tag object:

`8daaf7b12e71d3646eed787f040bf2899a69dc1c`

That makes `v31.1.0` a lightweight tag at the time of this review.

GitHub reports the target commit verification as:

- `verified: true`;
- `reason: valid`;
- a PGP signature is present in the commit verification payload;
- the commit is shown as committed by GitHub/web-flow.

This is useful commit-level provenance evidence. It is **not** the same thing as a separately signed release tag, a BitcoinII release-signing key, or signatures over the six binary archives.

Because the release is not marked immutable and the tag is lightweight, a careful verifier should record both the release-asset digests and the exact tag target commit at the time of verification.

## Checksum and signature publication status

The current six release attachments contain no `SHA256SUMS`, `SHA256SUMS.asc`, detached-signature file, or release-key file.

A repository search for `v31.1.0 SHA256SUMS` returned no current release-specific result. The source tree does contain inherited Bitcoin Core-style Guix/release-process documentation and verification utilities that mention checksum manifests and signatures. Their presence does **not** establish that BitcoinII used that process for `v31.1.0` or published the corresponding attestations.

## Authentication boundary

Current evidence supports these statements:

- the release, six uploaded assets, sizes, and GitHub-reported digests were observed;
- the current tag target was recorded;
- GitHub reports the target commit as cryptographically verified;
- the Windows Qt archive was independently downloaded/hashed by MoreBC2 and matched GitHub's digest;
- the extracted Windows Qt executable used in the test was not Authenticode-signed.

Current evidence does **not** establish:

- a maintainer-signed checksum manifest;
- detached signatures over the release assets;
- a documented BitcoinII release-signing-key trust path;
- independent hashes of the other five uploaded assets;
- binary-to-source equivalence;
- reproducible-build verification;
- platform code-signing status for every archive/executable.
