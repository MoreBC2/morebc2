**Category:** Releases
**Status:** Reviewed / Current plus historical evidence

## Summary

This page separates current GitHub-generated source-archive paths for BitcoinII Core `v31.1.0` from the independently fingerprinted historical `v29.1.0` source archives.

GitHub-generated source archives are snapshots produced from a Git ref. They are separate from uploaded release binary assets and do not prove that release binaries were built from that source.

## Why the tag target should be recorded

A generated source archive is based on the ref supplied to GitHub. A verifier who wants a durable audit record should therefore preserve the exact target commit observed at the same time as the archive download.

For the current v31 snapshot, record both:

```text
Tag: v31.1.0
Commit: 8daaf7b12e71d3646eed787f040bf2899a69dc1c
```

A human-readable tag name by itself is weaker evidence than a tag plus an exact object/commit target.

## Boundaries

GitHub-generated source archives are not, by themselves:

- uploaded release binaries;
- checksum manifests;
- detached signatures;
- signed source artifacts;
- proof that release binaries match source;
- proof that a release tag will never move.

Likewise:

- historical `v29.1.0` archive fingerprints do not authenticate `v31.1.0` source archives or binaries;
- a verified target commit does not prove binary reproducibility;
- a local archive hash needs an independently trusted expected value or attestation before it becomes publisher-authentication evidence.
