## Independent integrity record

All 10 uploaded assets were downloaded on 2026-08-27. Their local byte sizes and SHA-256 values matched the corresponding GitHub API metadata recorded in the dated audit.

The same historical audit also downloaded and hashed both GitHub-generated source archives. Exact hashes, source URLs, asset IDs, and retrieval boundaries are preserved in [Release-artifact authentication record — 2026-08-27](../verification/release-artifact-authentication-2026-08-27.md).

This is stronger integrity evidence than inventory metadata alone, but it is still not publisher-authenticated binary provenance: no publisher checksum manifest or release-asset signature tied to a BitcoinII-trusted release key was established.

## Historical source-archive relationship

## What this historical record does not prove

This page does not prove:

- publisher-authenticated expected hashes;
- release-asset signature verification against a trusted BitcoinII release key;
- reproducible builds;
- binary-to-source equivalence;
- current `v31.1.0` asset integrity or authenticity;
- current exchange/operator readiness by itself.

## Version boundary

Do not carry these historical values into current-release documentation.

In particular:

- `v29.1.0` asset names and sizes are not v31 asset names and sizes;
- v29 local hashes do not verify v31 downloads;
- v29 source-archive fingerprints do not verify v31 source archives;
- any v29 tag/commit signature observation is separate from the current v31 tag/commit state.
